# 5. Архитектурные решения

Статус всех пяти решений — принято для первой версии учебной модели. Дата — 8 ноября 2026 года. Они определяют будущую реализацию, а не утверждают наличие работающего приложения.

| ADR | Выбор |
| --- | --- |
| [001 — границы сервисов](0001-service-boundaries.md) | Владение данными и независимость отказов, включая вариант монолита |
| [002 — согласование аренды](0002-rental-orchestration.md) | Оркестрация и неизвестный результат выдачи |
| [003 — оплата картой](0003-card-billing.md) | Периоды, задолженность и исправление переплат |
| [004 — доставка и идемпотентность](0004-delivery-and-idempotency.md) | Kafka, consumer groups, offsets, outbox/inbox и сверка провайдера |
| [005 — офлайн-возвраты](0005-offline-returns.md) | Локальный журнал, время приёма и восстановление оборудования |

У каждого ADR есть контекст, варианты, решение и последствия. При изменении значимого ограничения во второй части нужно обновить решение и все затронутые контракты/диаграммы, а не только обработчик.
